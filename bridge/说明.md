# 微信 ↔ Claw Agent 桥接

微信发消息 → 本机 Claw Agent 干活 → 回复回微信。不走 OpenClaw，直接用腾讯 iLink 协议。

## 启动
双击 `start-bridge.bat`，或手动：
```bash
export WECHAT_BRIDGE_HOME="<本目录>"
python watchdog.py      # 看门狗：自动拉起并保活下面两个
```

## 三个进程
| 脚本 | 作用 |
|---|---|
| relay.py daemon | 长轮询收微信消息、发送回复 |
| worker.py | 微信消息 → POST /api/chat → 写回复 |
| watchdog.py | 每 20 秒保活（常驻，无时长上限） |

## 关键设置
- **模型**：worker 强制 `CLAW_MODEL=wb:auto`（云端）。**绝不用本地模型**——本机 MiniCPM5-2B 仅 1.4 tokens/s，会卡死。
- 环境变量：`CLAW_MODEL` / `CLAW_SESSION`(默认 wechat) / `CLAW_PERMISSION`(默认 standard)
- 凭证在 `secure/`（含 bot_token，勿外传），游标在 `state/cursor.json`

## 目录
- `inbox/` 入站消息（处理后移入 `inbox/done/`）
- `outbox/` 待发回复（发出后移入 `outbox/sent/`）
- `logs/` worker.log / daemon.log / watchdog.log

## 排错
- 显示未登录 → 确认设了 `WECHAT_BRIDGE_HOME`
- 回复卡住 → 查 /api/status 的 running，若为 true 说明本地模型被拉起
- daemon.log 的 "Long poll deferred: read timed out" 是正常的长轮询超时重试
- 重新扫码登录：`python login_qr.py`
